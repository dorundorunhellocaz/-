# AI 휴머노이드 반려로봇 기반 실버케어 플랫폼 (데모)

> **프로젝트명**: AI 휴머노이드 반려로봇 기반 노인 정신건강 진단·증진 및 신체활동 유도 플랫폼
> **프로젝트 목표**: 어르신 곁의 AI 반려로봇이 대화(정서·인지)와 동작(신체활동)을 코칭하고, 그 데이터를 보호자·전문가가 실시간으로 공유하는 융합 돌봄 플랫폼의 **발표 자료**와 **모니터링 웹앱 프로토타입**을 정적 웹(HTML/CSS/JS)으로 구현

---

## 1. 현재 완료된 기능

### ① 프로젝트 허브 (`index.html`)
- 프로젝트 개요·기획 배경·3대 기능 영역·산출물을 정리한 랜딩 페이지
- 발표 자료와 웹앱 프로토타입으로 이동하는 진입점
- 히어로 요약 지표, 반응형 카드 그리드, 시맨틱 마크업 + 스킵 링크

### ② 발표용 프레젠테이션 (`presentation.html`) — 총 8슬라이드
| # | 슬라이드 | 핵심 내용 |
|---|---|---|
| 1 | 표지 | 프로젝트명·서브타이틀, 대상/핵심기술/단계, 로봇 일러스트(SVG) |
| 2 | 기획 배경 및 필요성 | 고령화·고립, 정신건강·인지 저하, 신체활동 부족, 조기 발견 공백 + **문제의 악순환 구조** 도해 |
| 3 | 프로젝트 개요 | 목표·접근·연결 + 플랫폼 핵심 특성 4가지 |
| 4 | 주요 기능 3대 영역 | ① 정서 교감 & 인지 훈련(NLP·감정인식) ② 맞춤형 신체활동 코칭(동작인식·자세교정) ③ 원격 모니터링(보호자/전문가 연동) |
| 5 | 시스템 아키텍처 & 관련 기술 | 엣지 → AI 추론 엔진 → 플랫폼(클라우드) → 사용자 접점 **4계층 가로형 도해** |
| 6 | 데이터 활용 방안 | 수집→정제·가명처리→분석→개인화→검증 **5단계 파이프라인**, 데이터→지표 매핑 표, 개인정보·윤리 원칙 |
| 7 | 결과물 & 추진 일정 | **5단계 운영 계획**(요구사항 분석→설계/프로토타입→핵심 기능 개발→연동/PoC→피드백 검증), 간트 차트, 최종 결과물 4종 |
| 8 | 마무리 | 제안 요약, 파트너/자문/투자 요청, 다음 단계 |

**발표 기능**
- 이전/다음 버튼, 슬라이드 인디케이터(dots), 진행 바, 슬라이드 카운터
- 키보드: `←/→`, `Space`, `PageUp/PageDown`, `Home/End`, `F`(전체화면), `P`(PDF 저장)
- 모바일 터치 스와이프, `#slide-{n}` 해시로 특정 슬라이드 공유
- **PDF 저장**: 인쇄 시 1슬라이드 = 1페이지(A4 가로)로 출력
- 컨테이너 쿼리(`cqw`) 기반 스케일링으로 어떤 화면에서도 16:9 비율 유지

### ③ 모니터링 웹앱 프로토타입 (`app.html`) — 4개 탭
1. **메인 대시보드** — 오늘 정서 안정 지수/우울 위험 지수/신체활동 달성도/대화 시간 지표 카드, 정서 상태 막대 차트(우울·안정·기쁨), 활동 달성 도넛 차트, 펫로봇 연결 상태(배터리·동기화·센서), 최근 대화 요약 카드(감정 태그 포함)
2. **정신건강 & 인지 훈련 리포트** — 주간/월간 전환되는 감정 분석 추이 선형 차트, 인지 훈련 종합 점수 + 기억력 정확도 복합 차트, 항목별 결과 표(난이도 조정 표시), 분석 인사이트 & 권장 개입
3. **신체활동 코칭 기록** — 자세 분석 레이더 차트(관절 부위별 정확도), 자세 교정 피드백 목록(감지 시각·점수), 개인화 권장 운동 루틴, 주간 활동량 막대 차트(권장선 포함)
4. **실시간 모니터링 & 긴급 알림** — 긴급 알림 목록(심각도별 색상, 상태 필터), 알림 상태 변경(확인/처리 완료/재개), 펫로봇 원격 상태 점검 표, 실시간 이벤트 타임라인(자동 스트리밍), **돌봄 노트 CRUD**(등록·고정·삭제)

**웹앱 기능**
- 역할탭 접근성(`role="tab"`/`aria-selected`, 방향키 이동), `aria-live` 상태 알림, 스킵 링크
- 데이터 소스 배지: 테이블 API 연결 성공 시 `live DB 연결됨`, 실패 시 `시연 데이터 모드`
- 이상 상황 시뮬레이션 버튼(긴급 알림 생성), 원격 상태 점검 버튼
- 리포트 인쇄(인쇄 시 사이드바·툴바 숨김)
- 반응형: 980px 이하에서 사이드바가 상단 가로 내비게이션으로 전환

## 2. 현재 기능 진입 URI (경로 및 파라미터)

| 경로 | 설명 | 파라미터 |
|---|---|---|
| `index.html` | 프로젝트 허브(랜딩) | — |
| `presentation.html` | 발표 자료(8슬라이드) | 해시 `#slide-1` ~ `#slide-8` 로 특정 슬라이드 진입 |
| `app.html` | 모니터링 웹앱 | 해시 `#dashboard` / `#reports` / `#activity` / `#monitoring` 로 탭 진입 |

**테이블 API 엔드포인트** (앱에서 `fetch` 로 호출)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `tables/alerts?page=1&limit=100&search=&sort=` | 긴급 알림 목록 조회 |
| POST | `tables/alerts` | 알림 생성(이상 상황 시뮬레이션 시) |
| PATCH | `tables/alerts/{id}` | 알림 상태/담당자/메모 수정 |
| GET | `tables/care_notes?page=1&limit=100` | 돌봄 노트 목록 조회 |
| POST | `tables/care_notes` | 돌봄 노트 등록 |
| PATCH | `tables/care_notes/{id}` | 노트 고정 여부 변경 |
| DELETE | `tables/care_notes/{id}` | 노트 삭제(소프트 삭제) |

## 4. 데이터 모델 및 저장소

### 테이블 스키마

**`alerts` (긴급 알림)**
| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | text | 알림 고유 ID |
| `elder_name` | text | 대상 어르신 이름(가명) |
| `severity` | text | `info` / `warning` / `critical` |
| `category` | text | 정서 / 인지 / 활동 / 연결 / 응급 |
| `message` | text | 알림 내용 |
| `detected_at` | datetime | 감지 시각 |
| `status` | text | `open` / `acknowledged` / `resolved` / `false_alarm` |
| `assignee` | text | 담당자 |
| `note` | rich_text | 처리 메모 |

**`care_notes` (돌봄 노트)**
| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | text | 노트 고유 ID |
| `elder_name` | text | 대상 어르신 이름(가명) |
| `author` | text | 작성자 |
| `role` | text | 보호자 / 전문가 |
| `category` | text | 정서 / 인지 / 활동 / 일반 |
| `content` | rich_text | 노트 내용 |
| `created_at` | datetime | 작성 시각 |
| `pinned` | bool | 상단 고정 여부 |

### 데이터 흐름
```
[펫로봇 센서] 음성·표정·동작 데이터
      ↓ (가명처리)
[플랫폼] 대화/감정·동작인식 데이터 저장
      ↓ (테이블 API)
[웹앱] alerts · care_notes 조회/수정  →  보호자·전문가 대시보드
```
- **실시간성**: 알림 상태 변경·노트 등록/삭제는 즉시 테이블 API에 반영(PATCH/POST/DELETE)되며, 실패 시 UI를 원상 복구하고 오류 토스트를 표시
- **폴백**: 테이블 API를 사용할 수 없는 환경(로컬 파일 직접 열기 등)에서는 내장 시드 데이터로 자동 전환하여 모든 화면이 동작
- 차트 데이터(정서 추이·인지 점수·자세 정확도·활동량)는 시연용 예시 값이며, 실서비스에서는 위 데이터 모델의 시계열 집계 결과로 대체

## 6. 아직 구현되지 않은 기능 (정적 사이트 한계)

1. **실제 로봇·센서 연동** — 로봇 하드웨어, STT/TTS, 카메라 비전, 관절 센서와의 실시간 통신
2. **실제 AI 모델 추론** — NLP·감정인식·자세 분석·추천 모델 서버(API 키/인증 필요)
3. **실제 데이터 수집 파이프라인** — 서버사이드 수집·전처리·스케줄러
4. **푸시 알림** — 보호자 스마트폰으로의 SMS/푸시 발송(서버 발송 인프라 필요)
5. **사용자 인증·권한 관리** — 보호자/전문가 계정, 기관별 접근 제어(정적 사이트에서는 안전한 인증 불가)
6. **다중 어르신 관리** — 현재는 단일 대상(김순자 가명) 기준 프로토타입
7. **리포트 자동 생성·배포** — 정기 리포트 파일 생성 및 이메일 발송

## 7. 권장 다음 단계

1. **백엔드 연동**: 로봇 게이트웨이 → 수집 API → 분석 파이프라인 → 웹앱 조회 구조 구축
2. **인증·권한**: 보호자/전문가/기관 역할별 접근 제어(Hosted route admission 규칙 + 앱 내 레코드 권한)
3. **다중 대상 지원**: 어르신 목록 화면, 대상 전환, 기관 단위 대시보드
4. **알림 신뢰도 개선**: 오탐(false alarm) 피드백 루프를 통한 알림 민감도 자동 조정
5. **실증(PoC) 지표 정의**: 정서 지수 개선율, 활동 지속률, 낙상 위험 감소 등 효과성 측정 항목 확정
6. **접근성·시니어 UI 검증**: 고령 사용자 대상 사용성 테스트(글자 크기, 대비, 터치 영역)
7. **프로토타입 고도화**: 실측 데이터 기반 차트 교체, 리포트 PDF 자동 생성
